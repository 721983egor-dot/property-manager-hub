# CRM → финансовый календарь

При успешном закрытии аренды `crm_close_won_finance` атомарно сохраняет условия,
бронь (по флажку), полное покрытие сезонных цен и ожидаемые поступления компании.
Разовая комиссия задаётся суммой и датой; ежемесячная — процентом или фиксированной
суммой. Счёт выбирает администратор. Полная аренда хранится как `rental_turnover`
для сравнения, в `payments.amount` записывается только комиссия компании.

Ежемесячный платёж приходится на указанное число (31 сдвигается на последний
день короткого месяца). Включаются даты `start_date <= due < end_date`.
Если день оплаты первого месяца раньше начала аренды, первый ежемесячный платёж
попадает в следующий месяц. Сезон определяется по дате платежа, без дневного
пропорционального расчёта. Разовая комиссия задаётся независимо.

Уникальность `(deal_id, crm_charge)` и существующая уникальность
`(booking_id, management_period)` защищают от повторов. Повтор одинакового
закрытия безопасен. Ошибка откатывает всю операцию. Старые сделки автоматически
не получают новый график, чтобы не продублировать вручную заведённые доходы.

Редактор связанной брони использует атомарный `crm_save_finance_booking`.
Сроки, цены периодов и день оплаты пересчитывают неоплаченные платежи. Оплаченные
и частично оплаченные записи сохраняются целиком. Отмена убирает неоплаченные
ежемесячные записи; разовая комиссия остаётся. Удаление связанных броней запрещено,
вместо этого используется отмена. Прямые правки финансовых условий брони и периодов блокируются триггером, чтобы другой редактор не обходил пересчёт.

CRM-аналитика различает период закрытия сделок и доход по датам платежей.
В блоке дохода учитываются все связанные договоры выбранного источника/менеджера,
включая закрытые раньше. План — по planned_date, факт — по paid_at. У текущей
модели платежа одна дата факта, поэтому частичные оплаты отражаются общей суммой
на сохранённую дату; журнал отдельных поступлений не добавлялся.

Ассистент: getCrmResults возвращает commission (plan/actual/turnover),
proposeDealWon включает счёт, разовую комиссию и seasons; подтверждённый
closeDealWon использует тот же атомарный RPC. Существующие audit triggers
фиксируют изменения. Доступ к финансовой аналитике и RPC — администратор.

Проверки:

```
node --experimental-strip-types --test src/lib/crm-commission-model.test.ts src/lib/crm-results-model.test.ts src/lib/finance-rental-model.test.ts
```

Изолированная SQL-проверка без подключения к рабочей БД, с PGlite из npm:

```
npm install --prefix /tmp/rm-crm-check @electric-sql/pglite
PGLITE_MODULE=/tmp/rm-crm-check/node_modules/@electric-sql/pglite/dist/index.js node scripts/tests/crm-commission.mjs
```

Она проверяет доступ, сезонность, отдельный оборот, откат при ошибке,
идемпотентность, оплату 31 числа, пересчёт и сохранение оплаченной истории.
