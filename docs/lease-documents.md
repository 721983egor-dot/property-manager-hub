# Подготовка документов аренды

Входы: кнопка «Договор аренды» в сделке аренды, брони и объекте РМ; закрытые
«Паспортные данные» в карточке клиента; `/leases?bookingId=...` для ссылки из
ассистента. Новый функционал доступен только администратору, включая серверный API.

Для управления подписант — ИП или представитель по доверенности. Для «Только
комиссия» доступны собственник, представитель и ИП. Реквизиты ИП запоминаются
отдельно. Собственник выбирается из клиентов, его паспорт хранится в том же
закрытом механизме, что паспорт арендатора.

Источник условий — существующая долгосрочная бронь. Стоимость, сезонные периоды,
сроки, залог и день оплаты берутся из неё. Их изменение выполняется в редакторе
брони, который синхронизирует финансы. Договор не создаёт платежей и не закрывает
сделку автоматически. При подтверждении подходящая сделка связывается с бронью; если её нет, создаётся новая сделка аренды. При нескольких подходящих сделках требуется выбрать нужную;
проверяются клиент, объект и отсутствие другой связанной брони.

Первый шаблон намеренно не утверждён и содержит демонстрационный текст. Для
рабочих договоров администратор загружает DOCX или вставляет свой согласованный
текст, расставляет макросы и отмечает шаблон проверенным. Импортируется основной
текст Word, исходные шрифты/таблицы не переносятся. Приложения — акт и опись —
также редактируются. Неутверждённый шаблон формирует только документ с заметной
пометкой «ЧЕРНОВИК». Неполные паспортные данные блокируют формирование даже черновика.
Шаблон не генерируется ИИ и не заменяет проверку текста пользователем.

Комплект PDF + DOCX сохраняется одной версией в брони. Каждая версия содержит
снимок проверенных сторон, шаблона и условий. Последующие изменения клиента или
брони не переписывают файлы. Повтор requestId безопасен; другой payload с тем же
requestId отклоняется. Сохранение данных сторон и связи сделки выполняется
атомарным RPC. При сбое рендера/хранилища версия отмечается failed; номер не теряется.
Подписанный PDF прикрепляется к подготовленной версии и отмечает её подписанной;
электронного подписания или автоматической отправки арендатору нет.

Паспорта, черновики условий, снимки документов и реквизиты ИП зашифрованы AES-256-GCM.
Ключ `LEASE_DATA_KEY` — 32 байта в hex, только runtime окружение app/preview-app.
Сохраняйте его вместе с защищёнными резервными копиями окружения: без прежнего ключа
зашифрованные записи не восстановить. В миграциях и Git ключа нет. AAD привязывает
шифротекст к клиенту/версии/типу файла. Для приватных таблиц отсутствуют прямые grants
anon/authenticated. Storage bucket lease-private закрыт; ограничительная RLS-политика
запрещает прямое чтение даже при наличии будущей широкой политики. Файлы в нём
дополнительно зашифрованы; скачивание — через API администратора без публичных ссылок.
В activity_log пишутся события и идентификаторы, без паспортных полей.

Фото JPG/PNG/WebP до 10 МБ распознаются Tesseract rus+eng на VPS; изображения не
передаются языковой модели. Временный файл закрыт и удаляется после обработки;
сканы в клиенте не сохраняются. Распознанные поля — кандидаты, требуется проверка.
Первый вариант рассчитан на паспорт РФ (серия 4, номер 6 цифр); плохое фото или
недостающая регистрация требуют нового фото/ручного ввода. Telegram: страницы одного
человека — одним альбомом; разные альбомы не смешиваются. Черновик распознавания
привязан к администратору и личному чату и истекает через 24 часа.

Ассистент: getLeaseContext отдаёт маску паспорта и список пропусков;
proposePrepareLease, proposeSaveClientPassport, proposeLeaseCompany,
proposeLeaseTemplate → подтверждённые prepareLease/saveClientPassport/saveLeaseSetting.
Параметры подготовки и настроек в предложениях шифруются, в общем журнале и контексте
ИИ остаются ссылки. Telegram-подтверждение привязано к автору и атомарно захватывается.
PDF/Word после подтверждения отправляются только в связанный личный чат этого автора.

Тесты (без реальных паспортов и без записей в рабочей базе):

```
node --import tsx --test scripts/tests/lease-documents.ts
PGLITE_MODULE=/tmp/rm-crm-check/node_modules/@electric-sql/pglite/dist/index.js node scripts/tests/lease-documents-db.mjs
```

Проверяется шифрование, AAD/повреждение, отсутствие ключа, варианты подписанта,
полнота данных, сезонные цены, животные, приложения, импорт DOCX, атомарность,
права, идемпотентность и неизменяемость версий. PDF и Word визуально проверяются
на сгенерированных вымышленных данных. Full tsc в исходном проекте содержит
прежние ошибки, новые файлы проверяются отдельно; build и lint обязательны.

Зависимости Start/Router согласованы на версии с исправлением
https://github.com/advisories/GHSA-qx66-fv34-fjm8 . Защита Bun minimumReleaseAge
сохранена, исключения для новых библиотек не добавлялись. Для рендера используются
PDFKit, docx и Noto Sans (SIL OFL, лицензия в assets/lease-fonts).
