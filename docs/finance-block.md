# Финансы в RM OS

Нативный блок учёта. **Адеск не подключаем** — свой UI в той же логике (календарь по дням, карточка контрагента, обязательства).

Тест: [preview-rm-os.residence-more.ru](https://preview-rm-os.residence-more.ru) → меню **Финансы**. Код: SHA `805bd94`, PR [#20](https://github.com/721983egor-dot/property-manager-hub/pull/20) (продолжение [#18](https://github.com/721983egor-dot/property-manager-hub/pull/18)).

**Доступ:** только Администратор. Менеджерам не показывать, пока Егор явно не откроет.

## Что открыть

| Раздел | Путь |
| --- | --- |
| Платёжный календарь | `/finance/calendar` |

Логин: https://preview-rm-os.residence-more.ru/auth

## Календарь (как в Адеске)

1. Ячейка дня: входящий остаток, приход (зелёный), расход (красный), Δ, исходящий остаток. Дни с минусом — «Разрыв в XK ₽».
2. **Плюсик на дате** → Приход / Расход → боковая форма на эту дату: сумма, счёт (Основной/Касса), статья, дата, проект (объект), контрагент, описание. Галочки: учитывать в обязательствах, начислить на другую дату, повторять 12 мес. Файлы не храним.
3. Переключатель **Суммы / Операции**. График **Деньги на счетах** — прогноз остатка, «Сегодня», красный пунктир ниже нуля.
4. **Остаток** — начальный остаток месяца (в браузере).
5. Вид **Список** — таблица; **Оплачено** отмечает факт.
6. Статьи: аренда / депозит / выплата собственнику / подрядчик / расход агентства…

## Контрагенты (как в Адеске)

1. Список с фильтром-меткой: арендатор, собственник, подрядчик, сотрудник, депозит, прочее. Арендаторов и подрядчиков не ломаем.
2. Карточка: **Контрагент должен нам**, **Перевел нам**, **Мы перевели**, **Сальдо**; проекты, в которых участвует.
3. Вкладки **Деньги** (операции) и **Обязательства**. Кнопка «Добавить обязательство»: дата, сумма, направление (мы передали / нам передали), проект, описание.
4. По обязательству видно связанные платежи (если операция создана с галкой «Учитывать в обязательствах»).
5. Реквизиты и банк не ведём — заглушка вместо «Выставить счёт».

## Ассистент

Чтение: `listPayments`, `getPaymentCalendar`, `listOverduePayments`, `getFinanceSummary`, `listCounterparties`, `getCounterparty`, `listObligations`.

Предложения (кнопка подтверждения): `proposeCreatePayment` / `proposeUpdatePayment` / `proposeMarkPaymentPaid`, `proposeCreateCounterparty`, `proposeUpdateCounterpartyKind`, `proposeCreateObligation`.

Каждое выполненное действие пишется в `activity_log`.

## Пока нет

- Автопроведение из банка и выставление счетов
- Автогенерация строк из броней / `payment_day`
- Полный ДДС / ОПиУ / несколько юрлиц
- Теги и файлы у операций
