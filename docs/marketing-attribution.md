# Источники рекламы и обращения РМ ОС

Изменение подготовлено 30.10.2026 в ветке `preview`. Рабочий сайт ещё не обновлён.

## Что сохраняется

- Первый переход и последний значимый переход, окно хранения в браузере 90 дней.
- `utm_source`, `utm_medium`, `utm_campaign`, `utm_content`, `utm_term`, `yclid`.
- Страница входа, страница обращения, внешний referrer без query string, случайный visitor ID, ClientID Метрики при доступности счётчика.
- Направление формы: арендатор, собственник, обслуживание или общее обращение.
- Snapshot в заявке; snapshot при создании чата и отдельно у каждого нового входящего сообщения. Последующие сообщения не переписывают источник приобретения чата.
- При переводе заявки в сделку остаётся `lead_id`, а источник сделки получает рекламный канал.

Внутренние переходы и прямой возврат не стирают последнюю рекламную метку. Новый рекламный или внешний переход меняет последний источник целиком, не смешивая старый yclid с новой кампанией. Произвольные параметры URL, fragment и query string referrer не записываются. Блокировка localStorage оставляет атрибуцию в памяти вкладки; очистка браузера, другие устройства и приватный режим могут разорвать связь.

## Интерфейс и Ассистент

CRM → Заявки: источник у каждой заявки и сводка за 30 дней по последнему значимому переходу. Чаты: источник диалога и входящих сообщений. `getMarketingReport` использует тот же расчёт, доступ только действующему администратору. `getLeads` и `getChats` возвращают атрибуцию.

Посетители — уникальные идентификаторы браузеров в группе отчёта, не визиты Метрики. Между группами возможны пересечения. Заявки и чаты также могут принадлежать одному человеку: их нельзя складывать и называть уникальными лидами. Исторические заявки без меток показываются как неизвестный источник. Расходы Директа, коллтрекинг, сквозной ROMI и автоматическая отправка продаж в Метрику этим изменением не подключаются.

Сводка постранично читает до 10 000 строк каждого типа; если лимит достигнут, явно показывает неполноту. Публичные события ограничены 60 запросами в минуту на visitor ID, ID события уникален. Это не антибот/антифрод: браузерные метки можно подделать. Для форм передаётся стабильный submission ID для защиты от повторной записи при сетевом повторе.

## Цели Метрики — созданы в счётчике 97013300

Все условия — точное совпадение идентификатора целевого события.

| Цель                                | Идентификатор       | ID Метрики |
| ----------------------------------- | ------------------- | ---------- |
| Заявка арендатора сохранена         | `rm_lead_tenant`    | 676665001  |
| Заявка собственника сохранена       | `rm_lead_owner`     | 676665229  |
| Заявка на обслуживание сохранена    | `rm_lead_service`   | 676666113  |
| Общая заявка сохранена              | `rm_lead_general`   | 676666142  |
| Первое входящее сообщение сохранено | `rm_chat_started`   | 676666189  |
| Клик по телефону, не звонок         | `rm_phone_click`    | 676666263  |
| Переход в Telegram, не заявка       | `rm_telegram_click` | 676666302  |
| Переход в WhatsApp, не заявка       | `rm_whatsapp_click` | 676666347  |

Заявочная цель отправляется после подтверждения записи сервером. Чат — после сохранения первого входящего сообщения. Имена, телефоны и текст обращений в параметры целей не отправляются. Автоцели не удалены; новые кампании не запущены. После проверки рабочего сайта выбирать в Директе подтверждённую цель соответствующего направления, не клики контактов.

## Разметка двух рекламных черновиков

- Аренда, №715631828: `utm_source=yandex&utm_medium=cpc&utm_campaign=rm_rent_search&utm_content={ad_id}&utm_term={keyword}`.
- Собственники, №715631494: `utm_source=yandex&utm_medium=cpc&utm_campaign=rm_owners_search&utm_content={ad_id}&utm_term={keyword}`.
- `yclid` добавляет Яндекс при включённой автоматической разметке; фактическое наличие надо проверить на реальном рекламном переходе. Платный тестовый клик здесь не выполнялся.

## Выкладка и приёмка

1. Получить актуальную `origin/preview` и аккуратно совместить изменения: текущая среда не смогла подключиться к GitHub (DNS), SSH также заблокирован средой.
2. Выложить `preview` обычным процессом. Миграция `20261030120000_marketing_attribution.sql` только добавляет nullable-поля и новую таблицу, не переписывает старые заявки. Preview и production используют общую БД.
3. Проверить UI и запись тестовых обращений с согласованными тестовыми контактами: UTM → несколько внутренних переходов → форма; отдельные owner/tenant/service; запрос просмотра; первое и повторное сообщения в чате. Проверить отсутствие целей при ошибке сохранения и отсутствие второй заявки после повтора submission ID.
4. Проверить доступ: новый отчёт доступен администратору; аноним и менеджер не должны читать таблицу событий.
5. Рабочую систему обновлять только по явной команде владельца согласно AGENTS.md. После выкладки проверить на рабочем домене сохранённую заявку и цель в режиме отладки Метрики без покупки рекламного клика. До выкладки новые цели не получают события из старого кода.

## Локальная проверка

`node --import tsx --test src/lib/marketing-attribution.test.ts` — проверки сохранения/смены источников, TTL, направлений, приватных URL, группировки отчёта и блокировки хранилища/Метрики.

`npm run build` — сборка приложения. Общая проверка TypeScript содержит уже существующие ошибки репозитория; для оценки сравнивать с чистым HEAD, а не объявлять весь проект типобезопасным.
