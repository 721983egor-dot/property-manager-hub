# Интеграция Авито API в RM OS

## Цель

Заменить в разделе «Публикация и реклама» плашки «Скоро» для Авито на реальные данные: статус публикации, статистика по объявлениям и переписка с клиентами. Публикация объектов будет работать через фид Авито (Autoload), а статистика и чаты — через публичное API.

## Что получится

**1. Публикация / снятие с публикации на Авито**
- В карточке объекта в `/promo` появится рабочая кнопка «Опубликовать на Авито» / «Снять с Авито».
- Объект попадает в XML-фид, который Авито забирает по ссылке. После обработки фида объявление появляется/скрывается на площадке.
- В `property_listings` для платформы `avito` сохраняется `published`, `published_at`, `external_id`, `external_url`, `last_synced_at`.

**2. Статистика по каждому объекту**
- Просмотры объявления (uniq views).
- Просмотры контактов (contact views).
- Добавления в избранное.
- Период: 7 / 30 / 90 дней, как у сайта РМ.
- Данные приходят из Statistics API Авито [3](https://apis.io/apis/avito/avito-statistics-api/).

**3. Чаты / сообщения**
- Блок «Сообщения Авито» на странице объекта: список чатов и последние сообщения по этому объявлению.
- Возможность прочитать переписку; ответ пока только на стороне Авито (можно добавить позже).

**4. Ручная синхронизация**
- Кнопка «Синхронизировать с Авито» обновляет статусы объявлений, статистику и чаты.
- Автоматическое обновление токенов при истечении access_token.

## Порядок работы

### 1. Доступ к API
- Нужен аккаунт Авито для бизнеса и одобренное приложение на https://developers.avito.ru/applications [1](https://www.avito.ru/developers).
- Получить `client_id`, `client_secret` и разрешения на Autoload, Statistics, Messenger/Core API [2](https://www.avito.ru/developers/api-catalog).
- Сохранить `AVITO_CLIENT_ID`, `AVITO_CLIENT_SECRET`, `AVITO_ACCOUNT_ID` в секреты проекта.

### 2. Авторизация OAuth 2.0
- Добавить экран/диалог подключения Авито в RM OS.
- Пользователь переходит по ссылке Авито, подтверждает доступ, нас перенаправляет на `https://<домен>/api/public/avito/oauth/callback` с `code`.
- Сервер меняет `code` на `access_token` + `refresh_token` и сохраняет их в БД (`avito_tokens`).
- При каждом запросе проверяем срок access_token и обновляем его через refresh_token.

### 3. Хранение данных
- Новая таблица `avito_tokens`:
  - `id uuid PK`, `account_id bigint`, `access_token text`, `refresh_token text`, `expires_at timestamptz`, `created_at/updated_at`.
- Расширить `property_listings` не требуется — она уже поддерживает `avito`; нужно будет заполнять `external_id` (ID объявления на Авито) и `external_url`.
- GRANT + RLS по правилам проекта (чтение/запись для authenticated).

### 4. Синхронизация объявлений
- Фид: публичный маршрут `/api/public/avito/feed.xml`, формирует XML по объектам, у которых `property_listings.avito.published = true`.
- Пользователь указывает URL фида в кабинете Авито (Autoload) [4](https://www.avito.ru/business/tools/autoload). Альтернатива: если Realty/Item API позволяет напрямую создавать объявления в категории «Долгосрочная аренда», используем API; иначе оставляем Autoload.
- При включении/выключении публикации обновляем `property_listings` и, опционально, пересоздаём объявление через API.

### 5. Статистика
- Серверная функция `src/lib/avito.functions.ts`:
  - `syncAvitoStats(propertyId, from, to)` → запрашивает статистику по `external_id` и возвращает `{views, contacts, favorites, days[]}`.
- На странице `/promo/$id` добавить метрики Авито и линейный график рядом с сайтом РМ.

### 6. Чаты
- `syncAvitoMessages(propertyId)` → получает чаты, фильтрует по `item_id = external_id`, возвращает последние сообщения.
- Новый компонент `AvitoMessagesCard` в `/promo/$id`.

### 7. UI
- `src/routes/promo.index.tsx`: кнопка «Опубликовать» для Авито работает, плашка «Скоро» уходит.
- `src/routes/promo.$id.tsx`: блоки статистики Авито и сообщений вместо «Площадка не подключена».

### 8. Проверка
- Playwright: публикация/снятие, появление метрик, синхронизация.
- Проверить, что access_token обновляется без ручного переподключения.

## Техническая часть

- Язык/стек: TypeScript, TanStack Start `createServerFn`, Supabase.
- HTTP-клиент: `fetch` к `https://api.avito.ru`.
- Новые файлы:
  - `src/lib/avito.ts` — типы и константы (endpoints, scopes).
  - `src/lib/avito.functions.ts` — OAuth, фид, статистика, чаты.
  - `src/routes/api/public/avito/oauth/callback.ts` — OAuth callback.
  - `src/routes/api/public/avito/feed.xml.ts` — XML-фид.
  - компонент `src/components/AvitoMessagesCard.tsx`.
- Миграция: `avito_tokens` таблица с GRANT/RLS.

## Что понадобится от вас

1. Регистрация приложения на developers.avito.ru и согласование доступа.
2. `client_id`, `client_secret`, account ID (номер профиля Авито для бизнеса).
3. Решение, публиковать через Autoload-фид или через API. Для аренды недвижимости чаще используется Autoload.

## Ограничения и риски

- Авито выдаёт API доступ не всем аккаунтам — может потребоваться согласование.
- Прямое создание объявлений через REST API ограничено категориями; Autoload — универсальный, но требует настройки в кабинете Авито.
- Статистика и чаты появляются только после того, как объявление опубликовано и получило `item_id`.
