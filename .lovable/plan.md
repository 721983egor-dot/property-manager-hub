# RM OS — раздел «Объекты»

Внутренняя CRM для долгосрочной аренды. На этом этапе — только модуль «Объекты», полностью рабочий, с базой данных и загрузкой фото.

## Интерфейс

Светлая тема, много воздуха, аккуратная типографика, тонкие разделители, небольшие скругления (~8px), синий акцент — по референсу со скриншота. Desktop-first.

- Слева фиксированное вертикальное меню: логотип-марка «RM OS» сверху, один пункт — «Объекты» (активный). Больше пунктов нет.
- Справа рабочая область на всю высоту.

## Страница «Объекты» (`/`)

- Заголовок «Объекты», справа кнопка «+ Добавить объект».
- Вкладки: Все объекты / Активные / Архив.
- Панель: поиск (по названию и комплексу), фильтры «Тип объекта», «Комплекс», «Планировка», «Статус». Кнопка сброса фильтров.
- Таблица со строками объектов. Колонки: Объект (главное фото 64×48, название, ID), Тип, Комплекс, Этаж (7/18), Планировка, Санузлы, Статус (цветной бейдж), Действия.
- Бейджи: Свободен — зелёный, Сдан — синий, Забронирован — оранжевый, Архив — серый.
- Действия: иконка карандаша (редактирование) и меню «•••» → «Редактировать», «Переместить в архив» (или «Восстановить объект», если объект в архиве). Удаления из интерфейса нет.
- Внизу счётчик «Всего объектов: N».
- Вкладка «Активные» скрывает объекты со статусом «Архив»; «Архив» показывает только их.

## Форма объекта (`/objects/new`, `/objects/$id/edit`)

Отдельная страница, разбитая на блоки-карточки:

1. **Основная информация**: Название, Тип объекта (dropdown), Комплекс (поле с автодополнением по уже существующим комплексам), Этаж объекта и Количество этажей (два числовых поля), Планировка (1–8 комнат), Санузлы (1–5), Статус.
2. **Описание**: большое текстовое поле.
3. **Фотографии**: множественная загрузка, превью-сетка, перетаскивание для смены порядка, отметка «Главное фото», удаление. Главное фото попадает в таблицу.

Внизу: «Сохранить объект» и «Отмена». Та же форма используется при редактировании.

## Данные

Включаю Lovable Cloud (база + хранилище файлов).

Таблица `properties`: id (короткий числовой ID для отображения), название, тип, комплекс (текст + задел под связь), этаж, этажность, комнаты, санузлы, статус, описание, даты. Фото — отдельная таблица `property_photos` (url, порядок, признак главного), файлы в бакете `property-photos`.

Демо-данные (4 объекта из задания: ЖК Кислород, Морская Симфония, Романово, Олимпийский) вставляю миграцией сразу вместе со схемой, с сгенерированными фото.

## Технические детали

- TanStack Start + маршруты `index.tsx`, `objects.new.tsx`, `objects.$id.edit.tsx`.
- Чтения/записи через server functions; список кэшируется TanStack Query.
- Комплекс хранится строкой, но выделен в отдельный тип/утилиту, чтобы позже заменить на `complex_id` со связью.
- Доступ к таблицам: пока открытый для приложения (без модуля авторизации — он не входит в этап). Авторизацию и роли добавим отдельным этапом.
- Все цвета — семантические токены в `src/styles.css`, без хардкода.
