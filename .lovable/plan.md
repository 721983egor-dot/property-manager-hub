# Живой чат с клиентами

Сейчас в виджете на сайте только форма «оставьте сообщение» — она превращается в заявку. Сделаем настоящую переписку: клиент пишет прямо в окне чата на сайте, вы отвечаете из раздела «Чаты» в RM OS, ответ появляется у клиента в том же окне.

## Как это будет выглядеть

Для клиента:
- В виджете внизу справа остаются кнопки WhatsApp / Telegram / звонок, а ниже — окно переписки вместо формы.
- Пишет сообщение без регистрации, имя и телефон не спрашиваем. Можно вежливо попросить контакт прямо в переписке.
- Переписка сохраняется в его браузере: перешёл на другую страницу или вернулся позже — история на месте, ваши ответы видны.
- Пока никто не ответил, показывается подсказка «Обычно отвечаем в рабочее время. Срочно — напишите в WhatsApp».

Для вас:
- Новый раздел «Чаты» в меню RM OS: слева список диалогов (последнее сообщение, время, отметка непрочитанного), справа переписка и поле ответа.
- Общий счётчик непрочитанных в меню.
- Кнопка «Создать заявку из чата» — переносит диалог в «Заявки», если клиент оставил контакт.
- Диалог можно закрыть (в архив) и удалить.

Обновление — автоматическое: новые сообщения подтягиваются каждые несколько секунд с обеих сторон.

## Что не входит

- Telegram-пересылку и ответы из Telegram делаем следующим шагом, как договорились.
- Файлы и картинки в чате — не в этой версии (можно добавить позже).

## Техническая часть

База (одна миграция):
- `chat_threads`: id, visitor_key (уникальный ключ посетителя из браузера), name, phone, last_message_at, last_visitor_message_at, unread_count, status (`open` | `closed`), first_page, created_at, updated_at + триггер `set_updated_at`.
- `chat_messages`: id, thread_id (FK, cascade), direction (`in` | `out`), body, created_at, read_at; индекс по (thread_id, created_at).
- RLS включена, публичных политик нет: весь доступ — только через серверные функции с service_role, чтобы чужую переписку нельзя было вычитать по анонимному ключу. GRANT — только `service_role`.

Серверные функции `src/lib/chat.functions.ts` (все через `supabaseAdmin`, загружаемый внутри handler):
- Публичные: `startVisitorThread` (создаёт/находит тред по visitor_key), `sendVisitorMessage` (валидация zod: текст ≤ 2000, троттлинг — не чаще 1 сообщения в секунду и не более 30 в час на visitor_key), `fetchVisitorMessages` (только по своему visitor_key, отдаёт сообщения после указанного времени).
- Операторские: `fetchThreads`, `fetchThreadMessages`, `sendOperatorMessage`, `markThreadRead`, `setThreadStatus`, `createLeadFromThread`.

Фронтенд:
- `src/lib/site-chat.ts` — visitor_key в localStorage (`rm_chat_visitor`), локальный кеш последней истории.
- `src/components/site/SiteChatWidget.tsx` — вкладка переписки вместо `SiteLeadForm`: лента сообщений, поле ввода, опрос новых сообщений раз в 5 секунд, пока окно открыто.
- `src/routes/chats.index.tsx` — раздел «Чаты» (список + переписка), опрос раз в 8 секунд через TanStack Query `refetchInterval`.
- `src/components/AppShell.tsx` — пункт меню «Чаты» с иконкой и счётчиком непрочитанных, префикс `/chats` в `CRM_PREFIXES`.

Аналитика: первое сообщение клиента в чате пишется как событие `contact_click` по текущей странице объекта, если чат открыт со страницы объекта.
