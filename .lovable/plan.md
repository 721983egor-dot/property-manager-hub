# План: ИИ-помощник RM OS с полным доступом к системе

## Что строим
Помощник внутри RM OS, который знает всю систему — объекты, комплексы, клиентов, сделки (брони и аренды), заявки, чаты, публикации и статистику — и по команде выполняет действия: собирает подборки, публикует и снимает объявления по площадкам, заполняет карточку нового объекта, добавляет брони в календарь, меняет цены и статусы, готовит договор аренды.

Все действия, меняющие данные, выполняются только после вашего подтверждения.

## Про OpenAI и сервер в России
Прямой доступ к OpenAI с российского IP заблокирован. Поэтому помощник обращается не к OpenAI напрямую, а к шлюзу Lovable AI (`ai.gateway.lovable.dev`) — этот шлюз уже подключён в проекте, ключ `LOVABLE_API_KEY` есть. Первым шагом проверим доступность шлюза с сервера `217.12.40.8`:

- шлюз доступен → всё работает без VPN на сервере;
- шлюз недоступен → настраиваем один исходящий HTTPS-прокси на сервере только для ИИ-запросов (никакого VPN на весь сервер, сайт продолжает работать напрямую).

Ваша схема «сам делаю запрос через VPN или Telegram» тоже возможна, но тогда помощник не сможет автономно работать — команды всё равно проходят через сервер, поэтому канал наружу настраиваем один раз на стороне сервера.

## Доступ ко всем данным

Помощник получает набор инструментов чтения, покрывающий всю базу:

| Область | Что видит |
|---|---|
| Объекты | карточка целиком, цены, статусы, фото, комплекс, условия аренды, комиссия |
| Комплексы | описание, инфраструктура, объекты внутри |
| Клиенты | ФИО, телефон, комментарий, чёрный список, история сделок |
| Сделки | брони и аренды: периоды, цены, депозит, источник, статус, день оплаты |
| Календарь | занятость по датам, ближайшие заезды и выезды |
| Заявки | лиды с сайта, источник, статус, тема |
| Чаты | переписка с клиентами на сайте |
| Публикации | статус на сайте, Авито, ЦИАН, Яндексе, ошибки синхронизации |
| Статистика | просмотры, звонки, сообщения, избранное по площадкам и датам |

## Действия (только с подтверждением)

- Создать/обновить подборку и вернуть короткую ссылку.
- Опубликовать или снять объект — на всех площадках или на одной (например, только Авито).
- Создать новый объект и заполнить карточку по описанию.
- Изменить цену, статус, комиссию, депозит, условия.
- Добавить, перенести или отменить бронь; создать аренду.
- Завести клиента, обновить данные, поставить/снять чёрный список.
- Изменить статус заявки.
- Сформировать договор аренды с заполненными данными.

Порядок: помощник показывает карточку «что будет сделано» → вы нажимаете «Подтвердить» → изменение применяется и записывается в журнал.

## Договор аренды

Отдельный этап после базового помощника:
- Шаблон договора в системе (редактируемый текст с полями-подстановками).
- Помощник берёт данные из брони: объект, адрес, клиент, паспортные данные (добавим поля в карточку клиента), период, цена, депозит, день оплаты, условия.
- Результат — готовый документ, который можно скачать (PDF) и отправить клиенту.
- Договор формируется только после подтверждения; черновик можно править перед выгрузкой.

## Чтобы новые функции сразу были доступны помощнику

Инструменты помощника собираются из одного реестра (`src/lib/ai/tools/index.ts`). Правило проекта: каждая новая функция RM OS одновременно с интерфейсом получает инструмент в этом реестре. Реестр автоматически подхватывает все файлы из папки инструментов, поэтому при обновлении системы помощник получает новые возможности без отдельной настройки. Это правило зафиксируем в памяти проекта и в `AGENTS.md`.

## Как будем давать команды

1. Чат в RM OS (`/assistant`) — основной канал, история диалога сохраняется.
2. Telegram-бот — те же команды из мессенджера, подтверждения кнопками. Нужен токен бота от @BotFather.

## Технические детали

- Модель: через `createLovableAiGatewayProvider` (`src/lib/ai-gateway.server.ts`), с потоковой передачей ответа.
- Инструменты — AI SDK `tool()` с Zod-схемами; изменяющие помечены `destructiveHint` и всегда идут через подтверждение.
- Новые таблицы: `ai_action_proposals` (предложенные действия), `assistant_messages` (история диалога), `telegram_links` (привязка Telegram к пользователю RM OS), `contract_templates` (шаблоны договоров). Все с RLS для авторизованных пользователей.
- Новые поля в `clients` для договора: паспорт, дата рождения, адрес регистрации.
- Telegram webhook: `POST /api/public/telegram` с проверкой секретного токена.
- Секреты: `LOVABLE_API_KEY` (есть), `TELEGRAM_BOT_TOKEN` (нужен), опционально `AI_HTTPS_PROXY` для сервера РФ.

## Порядок работ

1. Проверка доступности шлюза ИИ с сервера РФ.
2. Реестр инструментов + чтение всех данных.
3. Подтверждение действий и журнал.
4. Изменяющие инструменты (подборки, публикации, объекты, брони, клиенты, заявки).
5. Telegram-бот.
6. Договор аренды.
