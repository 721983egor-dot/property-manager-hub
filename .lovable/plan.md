# План работ

## Задача 1 (сейчас). Перенос объектов с сайта residence-more.ru в RM OS

На странице https://residence-more.ru/rent найдено 33 ссылки: 31 объект и 2 комплекса-раздела (Лазурный берег 1 и 2), внутри которых лежат отдельные квартиры.

### Что делаю

- Прохожу по каждой ссылке, снимаю данные карточки и переношу их в новые объекты RM OS.
- С каждой страницы забираю: название, комплекс, тип объекта, район/адрес, координаты карты, площадь, спальни/планировку, этаж и этажность, санузлы, цену в месяц, летнюю цену (если указана «Июнь — Сентябрь»), страховой депозит, технику и дополнительные характеристики, описание, локацию, условия аренды, статус.
- Фотографии галереи скачиваю с сайта и загружаю в хранилище RM OS, первая становится главной.
- Комплексы «Лазурный берег 1» и «Лазурный берег 2» создаю как записи в разделе «Комплексы» (название, описание, инфраструктура, фото), а их квартиры привязываю к ним по `complex_id`. Для остальных объектов комплекс из карточки тоже подтягиваю или создаю, если такого ещё нет.
- Объекты создаются опубликованными (они уже открыты на сайте), статус — «Свободен», если на карточке «Свободен сейчас».
- Существующие 4 демо-объекта не трогаю; повторный запуск переноса не создаёт дублей — сверяю по адресу страницы-источника.

### Проверка

Показываю итоговый список: сколько объектов и комплексов создано, у кого не хватает данных (например, нет этажа или депозита), чтобы вы вручную дозаполнили.

### Технические детали

- Импорт разовый, скриптом на моей стороне: постраничный разбор HTML Tilda, загрузка фото в бакет `property-photos`, вставка строк в `properties`/`complexes`.
- В `properties` добавляю поле `source_url` (уникальное, nullable) — только чтобы не задваивать при повторном импорте.
- Существующая схема не меняется, новые сущности не создаются.

## Задача 2 (после переноса). Синхронизация календаря с Яндекс Путешествиями и Суточно.ру

Без Бново — можно. Площадки отдают и принимают занятость по ссылкам iCal, этого достаточно, чтобы даты автоматически закрывались в обе стороны. Ограничение одно: в iCal приходят только даты и служебный номер брони — ФИО и телефон гостя площадки не передают.

Бново нужен, только если хочется видеть данные гостя и суммы. Доступ к API Бново выдаётся по заявке — подключим отдельным этапом поверх той же схемы.

### Импорт занятости с площадок

- Для каждого объекта можно добавить несколько внешних календарей: источник (Яндекс Путешествия, Суточно.ру, Бново, другое) и ссылка .ics.
- Раз в 30 минут система забирает ссылки и создаёт/обновляет брони в календаре RM OS.
- Внешние брони видны в шахматке отдельным цветом с пометкой источника; даты правятся только на стороне площадки, комментарий и клиент — у нас.
- Брони, снятые на площадке, автоматически исчезают.
- В карточке объекта — статус синхронизации и кнопка «Синхронизировать сейчас».

### Экспорт нашей занятости

- Для каждого объекта — постоянная ссылка `/api/public/ical/<токен>.ics` для вставки в кабинеты площадок; в ленте все не отменённые брони, включая внешние.

### Технические детали

- Таблица `property_calendar_feeds` (объект, источник, url, токен, last_synced_at, last_error); в `bookings` — `external_source`, `external_uid`, `external_feed_id` с уникальным индексом.
- Импорт — публичный маршрут `src/routes/api/public/ical-sync.ts` по расписанию pg_cron с секретным заголовком; парсер VEVENT свой (ограничения Worker-рантайма).
- Экспорт — `src/routes/api/public/ical.$token.ts`, `text/calendar`, без персональных данных.
- DTEND в iCal — день выезда эксклюзивно: `end_date` = DTEND минус день.
