# План: ИИ-помощник RM OS с действиями и Telegram

## Что строим
ИИ-помощник, который по команде пользователя выполняет операции в RM OS: собирает подборки, публикует/снимает с площадок, заполняет карточку объекта, добавляет бронь/аренду в календарь, меняет цены и статусы, показывает статистику и заявки.

## Технический подход
- **Модель**: Lovable AI Gateway + `openai/gpt-6-astra` (или другая модель по запросу). Запросы идут с нашего сервера на шлюз Lovable, который сам обращается к OpenAI. Это позволяет обходить блокировку российских IP OpenAI без VPN на сервере, потому что исходящий IP к OpenAI — инфраструктура Lovable. Если шлюз по какой-то причине не будет доступен с сервера в РФ, настраиваем исходящий HTTPS-прокси/VPN на сервере.
- **Клиенты помощника**:
  1. Внутренний чат в RM OS (`/assistant`) — для менеджеров/владельца.
  2. Telegram-бот — команды из мессенджера.
- **Безопасность действий**: любая операция, которая меняет данные, сначала возвращает план действия; пользователь нажимает «Подтвердить» в чате или в Telegram, только тогда изменение применяется.

## Что войдёт в реализацию

### 1. Настройка подключения к ИИ
- Проверить/добавить `LOVABLE_API_KEY` в `.env` проекта и на сервере РФ.
- Создать единого провайдера `createLovableAiGatewayProvider` в `src/lib/ai-gateway.server.ts`.
- Добавить проверку связи: серверный health-вызов модели с выводом версии/статуса.

### 2. Инструменты (tools) для ИИ
Определить серверные функции-инструменты в `src/lib/ai/tools/`:
- `searchProperties` — поиск объектов по фильтрам (комплекс, комнаты, цена, статус, свободен/скоро освободится).
- `getPropertyDetails` — полная карточка объекта + фото + текущая бронь/аренда.
- `createSelection` — собрать подборку из найденных объектов, сохранить, вернуть короткую ссылку `/p/[code]`.
- `publishProperty` / `unpublishProperty` — публикация/снятие с сайта, Авито, ЦИАН, Яндекс (по отдельности или всех).
- `createProperty` — создать черновик объекта по описанию, сохранить, показать на подтверждение.
- `updateProperty` — изменить цену, статус, описание, комиссию и другие поля.
- `createBooking` / `createRental` — добавить бронь или аренду в календарь объекта с проверкой занятости.
- `getStats` — статистика просмотров/лидов/бронирований по объекту или за период.
- `getLeads` — список заявок, фильтр по статусу.
- `proposeAction` — универсальный «подготовить действие», который ИИ использует, когда сам не уверен.

Каждый инструмент читаемый (`readOnlyHint`) или изменяющий (`destructiveHint`). Все изменяющие сначала возвращают `proposedAction` и не меняют данные сразу.

### 3. Подтверждение действий
- Создать таблицу `ai_action_proposals` (RLS: пользователь видит только свои).
- При вызове изменяющего инструмента ИИ получает `proposalId`, который показывается в чате/Telegram с кнопкой «Выполнить» / «Отменить».
- Подтверждение выполняется отдельной серверной функцией `executeProposal`, которая проверяет владельца и применяет действие.

### 4. Чат внутри RM OS
- Доработать существующий маршрут `/assistant`.
- История сообщений: один диалог на пользователя, сохраняется в базе (`assistant_conversations`, `assistant_messages`).
- Сообщения рендерятся с markdown; действия показываются карточками с кнопками подтверждения.
- Внизу чата — поле ввода и кнопка микрофона (опционально, если выберем голосовой ввод позже).

### 5. Telegram-бот
- Добавить публичный endpoint `POST /api/public/telegram` для webhook от Telegram.
- Хранить `TELEGRAM_BOT_TOKEN` в секретах.
- При получении сообщения:
  1. Идентифицировать пользователя по Telegram ID (привязка к учётной записи RM OS).
  2. Отправлять текст в ту же ИИ-конвейер, что и веб-чат.
  3. Показывать ответ и кнопки подтверждения inline-клавиатурой.
- Команды `/start`, `/help`, `/status`.
- Обновление webhook на домен `residence-more.ru`/`rm-os.residence-more.ru` после публикации.

### 6. Интеграция и развёртывание
- Добавить `LOVABLE_API_KEY` и `TELEGRAM_BOT_TOKEN` в `.env.example` и в документацию по деплою на сервер РФ.
- После мержа в ветку и нажатия «Обновить систему» на сервере РФ проверить, что `/api/public/health` и `/api/public/telegram` отвечают.
- Настроить webhook Telegram через вызов `setWebhook`.

## Вопросы, которые нужно решить перед стартом
1. **Доступность шлюза**: проверим ping/запрос к `ai.gateway.lovable.dev` с сервера РФ. Если не работает — добавляем в план настройку исходящего HTTPS-прокси/VPN.
2. **Telegram-бот**: нужен токен бота от @BotFather. Попросите его заранее.
3. **Приоритет**: сначала делаем внутренний чат RM OS, затем Telegram; или сразу оба?

## Критерии готовности
- Менеджер пишет в чат RM OS: «собери подборку 2-комнатных в Актере до 300 тыс.» — ИИ возвращает список и ссылку `/p/...`.
- Менеджер пишет: «опубликуй объект №123 на Авито» — ИИ показывает карточку с кнопкой «Подтвердить»; после нажатия объект публикуется.
- Тот же диалог работает в Telegram.
