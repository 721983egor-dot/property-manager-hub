# ЦИАН: автопубликация и синхронизация через XML-фид

Объекты из RM OS попадают на ЦИАН автоматически: цена, описание, фото и статус обновляются сами, кнопки «Опубликовать» / «Снять с публикации» управляют присутствием объекта в фиде.

## Как это будет работать для менеджера

- В разделе «Публикация и реклама» у каждого объекта рабочие кнопки ЦИАН: «Опубликовать» — объект появляется в фиде и при ближайшей загрузке уходит на ЦИАН; «Снять с публикации» — объект убирается из фида и снимается на ЦИАН.
- Любое изменение в карточке объекта (цена, описание, фото, площадь) само попадает в объявление на ЦИАН — вручную ничего обновлять не нужно.
- Если у объекта чего-то не хватает (адрес, площадь, цена, этаж, фото, описание), под кнопкой видно, что дозаполнить — такие объекты в фид не попадают, чтобы ЦИАН не отклонил выгрузку.
- Настройка «Публиковать новые объекты автоматически» на странице настроек площадок: включена — любой новый объект с заполненными полями сразу попадает в фид; выключена — только по кнопке.

## Что делаем

1. **XML-фид**: новый адрес на сайте, который отдаёт файл со всеми объектами, отмеченными к публикации на ЦИАН, в официальном формате ЦИАН (feed v2, категории flatRent / houseRent / townhouseRent, долгосрочная аренда). Эту ссылку один раз вставляем в кабинете ЦИАН («Автозагрузка») — дальше ЦИАН сам забирает файл несколько раз в день.
2. **Фото в фиде**: фотографии сейчас лежат в закрытом хранилище со временными ссылками. Делаем постоянные адреса фото для фида (отдельный открытый раздающий адрес на нашем сайте), иначе ЦИАН не сможет их скачать.
3. **Управление публикацией**: в `property_listings` для платформы `cian` поле `published` становится переключателем «в фиде / не в фиде». Объекты, уже связанные сверкой, остаются опубликованными. При снятии запоминаем `unpublished_at`.
4. **Проверка перед публикацией**: серверная функция валидации обязательных полей (готовый список `missingCianFields` уже есть в `src/lib/cian.ts`) + показ списка недостающих полей на страницах `/promo`.
5. **Настройка автопубликации**: в `platform_credentials` для `cian` — флаг «автопубликация новых объектов». При включении в список фида автоматически попадают все объекты со статусом «Свободен» и заполненными полями.
6. **Интерфейс**: на страницах «Публикация и реклама» (список и карточка объекта) у блока ЦИАН — рабочие кнопки публикации/снятия, статус «в фиде», дата последней синхронизации, ошибки фида. В настройках площадки — ссылка на фид с кнопкой «Скопировать» и инструкция, куда её вставить в кабинете ЦИАН.

## Технические детали

- `src/routes/api/public/feeds/cian.xml.ts` — серверный роут: генерирует XML (feed_version=2) из объектов, где `property_listings.published = true` и платформа `cian`; переиспользует `buildCianOfferPayload` из `src/lib/cian-payload.server.ts`; `Cache-Control` с небольшим TTL.
- Фото: раздающий роут `/api/public/feed-photo/<path>` (стрим из приватного бакета через `supabaseAdmin`, `Cache-Control: public, max-age=86400`) — стабильные URL без истекающих подписей.
- Миграция: в `platform_credentials` — колонка `auto_publish boolean not null default false`; GRANT/политики не трогаем, таблица уже под `service_role`.
- Функции в `src/lib/cian.functions.ts`: `setCianPublished(propertyId, published)` — upsert в `property_listings` с проверкой обязательных полей; `setCianAutoPublish(enabled)`; `getCianFeedInfo()` — URL фида и счётчики (сколько в фиде, сколько отклонено валидацией).
- Обновление `src/routes/promo.index.tsx`, `src/routes/promo.$id.tsx` и блока настроек площадок: кнопки, статусы, недостающие поля, ссылка на фид.
- `external_id` в фиде = UUID объекта из RM OS, чтобы ЦИАН корректно обновлял уже связанные объявления (для уже связанных сверкой объектов в фиде указываем существующий `external_id` ЦИАН — проверим на первой загрузке по отчёту ЦИАН).

## Что понадобится от вас

1. В кабинете ЦИАН включить «Автозагрузку / фид» и вставить туда ссылку, которую я покажу в настройках.
2. После первой загрузки прислать мне отчёт ЦИАН об ошибках фида (если будут) — поправлю разметку под их валидатор.

## Проверка

- Юнит-проверка XML: валидная разметка, все обязательные теги, корректные категории.
- Ручная проверка: публикация/снятие объекта меняет содержимое фида; объект без цены в фид не попадает и показывает список недостающих полей.
